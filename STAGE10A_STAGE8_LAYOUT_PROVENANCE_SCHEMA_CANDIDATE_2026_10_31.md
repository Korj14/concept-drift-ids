# Stage-10A — Stage-8-compatible Phase-A/Phase-B provenance schema candidate

**31 October 2026 (Asia/Riyadh)**. **WARM engineering schema candidate, not governing methodology or changing-state authority.** Status remains exclusively in `STAGE10A_CURRENT_STATE_AND_RESUME.md`; the frozen master v1.1 and Stage-10A GoldenEye protocol remain authoritative. **Treatment execution: HOLD.**

## Reuse rationale

Retain accepted Stage-8 layout and concepts, rather than replacing the scientific execution path: `phase_a_shared_control_plane/seed-{seed}/` followed by `phase_b_symbolic_arms/seed-{seed}/`. Phase-A contains an attempted-run marker, input identity, six named raw evidence streams (`predictions`, `label_schedule`, `detector_observations`, `events`, `replay_transactions`, `checkpoint_chain`), shared identity and run manifest. Phase B contains `phase_b_manifest.json` and three arm folders with `arm_manifest.json` and per-arm payloads. Stage-8 hash/linkage conventions and exclusive/write-once principles are retained. **Synthetic records project this shape; they are NOT valid Stage-8 run artifacts and cannot be passed to a treatment executor.**

A Stage-10A-specific supplementary `stage10a_provenance_seal.json` binds raw Phase-A file hashes, the accepted original-source and checkpoint receipt byte identities, seed-specific original checkpoint identity and frozen inherited preprocessing. Each synthetic arm binds the exact Phase-A shared identity and supplementary seal. A separate independent, read-only verifier reconstructs all fixture events from the fixture definition, checks immutable journal bytes and manifest descriptors, and refuses changed seal/arm references even when self-reported hashes have been recomputed.

## Explicit synthetic-only limits

`tools/stage10/stage10a_phase_compat_audit.py` accepts only 5,001–5,002 synthetic logical rows for five seeds, not 138,530 production rows. Its bounded test records do **not** represent real neural probabilities, detector behavior, replay selection, optimization, symbolic lifecycle, observed effects or valid production checkpoint chains. A zero-event detector/replay stream and a one-record synthetic checkpoint-chain token are scaffolding, **not proof of operational validity or of no genuine drift.** The test generator writes fixture JSON; the independent verifier never writes, imports neural modules, loads checkpoint binaries, or accesses raw CICIDS/Stage-10A outcomes. A successful result always sets real execution/provenance flags to **false**.

The current fixture deliberately uses `git_commit="unverified-synthetic"` and `runtime.fixture_only=true`. These are disqualifying in production. The seal is an integrity cross-reference, **not an authenticated witness of Git checkout, wall-clock order, fsync durability, or external attestation**; re-hashing one writer's files alone cannot prove chronology or trusted isolation. Earlier synthetic fsync-before-label testing remains separate evidence and must not be silently transferred to this validator.

## Production design requirements still requiring prospective review

1. **Entrypoint and custody.** Exact clean Git commit, Python 3.11.9, frozen dependency hashes/CPU thread environment, accepted checkpoint bytes, frozen preprocessing/thresholds/R0 and pinned source inputs must be independently attested before the real phase begins. The original source-only receipts remain immutable; neither must be regenerated.
2. **Phase-A full evidence.** Independently recomputable 138,530 complete predictions, label maturity and release ordering, detector observations/drift events, replay/reservoir selection, RNG/optimizer transactions, parent/child neural checkpoint bytes/state hashes and publication-effective clocks. The 69,260 offline evaluator-only boundary is not an adaptation input. Failure/partial attempts remain preserved; no overwrite or favorable-outcome filtering.
3. **Phase-B isolation.** All five complete Phase-A writers must seal before the three strictly read-only arm consumers begin; each arm references the exact raw Phase-A seal and frozen operator identity. Symbolic state/lifecycle changes are the treatment; any neural/control mismatch is Class A. Checkpoints read by a symbolic model resolver remain subject to frozen read-only access and independent byte-chain verification.
4. **Evaluator and audit.** Independent offline reader only after sealed streams, original E1/E2/E3 and paired n=5 test/sign/Holm family, no pseudoreplication or post-outcome retuning. Trusted raw trace hashes and retrospective consistency cannot alone demonstrate *causal* read/write isolation; enforce access controls and a separate audit.
5. **Release.** Production schema cannot be promoted without a separate reviewed version/freeze and explicit user authorization. S10-04 second-environment selection/replication and other readiness gates remain unmet. No real checkpoint deserialization, neural prediction, C/D/D-periodic treatment, outcome or Stage-10A RELEASE occurs here.

**Decision at this checkpoint:** source-only production-schema **candidate** with synthetic tests, not production acceptance. Keep the prior independent synthetic envelope as separate WARM evidence; this document is narrower than and does not supersede frozen scientific rules.
